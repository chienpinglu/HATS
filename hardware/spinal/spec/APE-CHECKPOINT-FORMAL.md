# Checkpoint component: selected bounded formal properties

This is a deliberately limited S03 formal entry point, not full-core proof
closure. The authoritative result is generated by
[`formal/verify_checkpoints.py`](../formal/verify_checkpoints.py) at
`build/ape_formal/validation.json`. Only `passed_bounded` confirms that all
configured proof, cover and negative-control jobs completed. Compilation,
timeout, `running` and `failed_or_inconclusive` are not passes.

## Actual design under test

The driver consumes the unmodified Verilog produced by the current passing
recovery gate, checks its recorded hash and selects its `ApeCheckpoints` module.
It does not reimplement the component in Python or prove a software abstraction.
The full rename wrapper is unused in this proof; no PRF/commit/free-list claim
is inferred from the component result. The four RTL assertions are retained
alongside four independently authored harness assertions.

The selected configurations are 36 physical registers, eight ROB-indexed rows,
and one/four live checkpoints. An arbitrary constant chooses any row and any
physical tag from 1 through 35. Snapshot-value preservation is checked for
architectural field x10 only. Other map fields and P64 are covered by simulation,
not this selected formal gate.

## Properties and assumptions

The harness maintains an independent live-owner bitmap and history for the
watched row. Admission assumptions use this history, not the DUT's availability
output. Assertions check:

- Occupancy equals the owner count and admission availability matches capacity/clear.
- A live watched row returns its captured x10 snapshot field.
- Its selected reclaim bit records allocations after capture, excluding capture's
  own allocation and resetting on row reuse.
- The existing RTL checks for live resolution, legal capture, no dispatch on
  redirect and capacity are preserved in the formal model.

Assumptions constrain the component's legal input protocol: initial reset, no
simultaneous activity during reset/clear, capture only a free row below capacity,
resolve only a live row, no allocation/capture during redirect, and allocation
tags in 1..35. Snapshot data and squash masks are otherwise unconstrained. The
proof does **not** assume that a supplied squash mask means "younger"; calculating
the correct mask is the core's responsibility and remains outside this proof.

The clock-to-global-transition conversion models edge-triggered state and initial
reset. It is not a physical reset, clock-domain crossing or metastability proof.
There is no progress/fairness claim. The gate checks **12 global transitions**,
not 12 instructions or necessarily 12 clock cycles. This shallow bound is an
initial formal regression, not a replacement for the long RTL tests or unbounded
invariants required for stronger closure.

## Non-vacuity and failure detection

Separate reachability jobs, bounded at 16 global transitions, must reach full
capacity, redirect with a nonempty reclaim bit, reuse after redirect, and clear
after capture. The C4 case additionally reaches simultaneous correct resolution
and new capture. Every configured cover must be reached.

A negative control adds the intentionally false property that occupancy remains
zero even after a live capture. It must produce a counterexample, not a timeout
or elaboration failure. This checks the assertion pipeline; it is **not** a
mutated-DUT coverage score or a general proof of oracle independence.

During initial exploration, a direct SMT induction attempt did not establish an
unbounded invariant, and deeper SMT exploration hit solver time limits. Those
attempts are not passing proofs and are not interpreted as reachable RTL bugs.
The selected gate uses bounded SAT for safety and SMT for the concrete covers.
Strengthening the inductive relation and expanding field/configuration/depth
coverage remain required work, not silently relaxed acceptance criteria.

## Reproduction

Use Python 3.12+ and an installed Z3. Tool dependencies go in an ignored local
environment, without changing system Python. From `hardware/spinal`:

```sh
python3 -m venv .tools/ape-formal
.tools/ape-formal/bin/python -m pip install -r formal/requirements.txt
python3 tools/verify_ape_recovery.py
python3 formal/verify_checkpoints.py
```

The current semantic-boundary rerun passed both configurations at the same
12-global-step depth, all nine covers and both false-assertion controls. Its first
attempt reached the 180-second command wall limit in C4 and is retained locally
as `build/s03-checkpoint-formal-semantic-first-attempt.tar` (SHA-256
`065b84372cb91ef268b327feec857e306fe44257ec3116774e4e6b51965f2266`).
That attempt is not counted as a pass. The successful rerun used:

```sh
python3 formal/verify_checkpoints.py --solver-timeout 300 --wall-timeout 900
```

The report records these budgets; increasing them changes neither proof depth nor
assumptions/properties. Covers and negative-control solver limits are unchanged.

The driver requires the exact pinned Python package set, records Yosys/Wasm and
Z3 identities, uses a workspace-local Wasm cache, and checks source stability.
Generated SMT, logs and cover waveforms are hashed in the result. The result
does not require another sbt run and may run alongside a read-only RTL regression
after recovery artifacts have been frozen. Do not edit formal inputs during it.

Tool references: [Yosys](https://github.com/YosysHQ/yosys) and the
[YoWASP distribution](https://github.com/YoWASP/yosys). This repository's harness
is original; downloaded tool implementations remain in ignored local storage.

## Remaining proof scope

Committed/free exclusion, map injectivity across the full PRF, retirement,
correct age-based squash selection, preserved older external transactions,
late-completion rejection, generation wrap, full reset/relaunch interaction and
unbounded invariants are not established by this component gate. Issue #4 remains
open even if both selected bounded configurations pass.
